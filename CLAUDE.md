# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`bixverse.gpu` is an R package providing GPU-accelerated algorithms (kNN search, k-means, PCA, Harmony, UMAP, tSNE, parametric UMAP, correlations) that plug into the `bixverse` / `manifoldsR` ecosystem. The heavy lifting is Rust, exposed to R via `extendr`. GPU code runs on WGPU via `cubecl` / `burn` — portable across vendors (no CUDA required).

## Common commands

Rextendr-based workflow — run from an R session at the repo root:

```r
devtools::load_all()          # build the Rust static lib + load the package
devtools::document()          # since rextendr 0.5.0 this also compiles Rust and regenerates R/extendr-wrappers.R from #[extendr] fns — use this after editing Rust
rextendr::clean()             # nuke cargo build artifacts (e.g. after Cargo.toml changes)
tinytest::test_package("bixverse.gpu")   # run the full test suite
tinytest::run_test_file("inst/tinytest/test_gpu_kmeans.R")  # run one test file
```

Rust builds live under `src/rust/target/` and are always release (`opt-level = 3`) — CRAN policy. `DEBUG=1` is ignored by `tools/config.R`; do not add a debug path.

R CMD check runs in CI (`.github/workflows/R-cmd-check.yml`) on macOS and Ubuntu; Linux CI installs `libvulkan1` / `mesa-vulkan-drivers` and sets `WGPU_BACKEND=vulkan`.

Formatting: R code uses `air` (`air.toml` present). Rust is stock `cargo fmt`.

## Architecture

The package is a thin R shim over a Rust crate. Three layers, top-down:

1. **R user API** (`R/*.R`) — friendly, validated wrappers. `sc_gpu.R` (single-cell workflows, S7 generics dispatching on `SingleCells` / `SingleCellsMultiModal` from `bixverse`), `umap_gpu.R`, `parametric_umap.R`, `ml_gpu.R` (k-means), `nn_gpu.R` (kNN graphs). Argument checks use `checkmate` + local `checkmate_extensions.R` (`assertNnParamsGpu`, `assertUmapParamsGpu`, etc.). Parameter builders live in `param_wrappers.R` (`params_sc_cagra`, `params_sc_ivf`, `params_nn_gpu`, `params_umap_gpu`, `params_kmeans_gpu`, `params_parametric_umap`, `params_sc_harmony_v2_gpu`) — each returns a plain named list that the corresponding assert function then validates before it crosses into Rust.
2. **extendr bridge** (`R/extendr-wrappers.R`) — GENERATED by `rextendr::document()` from `#[extendr]` attributes in Rust; never edit by hand. Any change to a Rust-exposed function signature or doc comment requires re-running `document()`.
3. **Rust crate** (`src/rust/`, package name `bixverse_gpu`). `src/lib.rs` holds all `#[extendr]` entry points plus the `extendr_module!` registration and the `PUmapModel` backend-agnostic wrapper. Subdirectories:
   - `embeddings/` — `umap_gpu.rs`, `tsne_gpu.rs`, `parametric_umap.rs` (neural-net UMAP with GPU + CPU backends).
   - `single_cell/` — `knn_gpu.rs` (CAGRA / IVF / exhaustive), `pca_gpu.rs` (sparse randomised SVD), `harmony_gpu.rs`.
   - `ml/clustering.rs` — k-means.
   - `utils.rs` — R↔Rust matrix converters (`r_matrix_to_faer_fp32`, `faer_to_r_matrix`, `nearest_neighbours_to_rust`).

Backends:
- `GpuBackend = Autodiff<Wgpu>` — the WGPU/cubecl path for all "GPU" algorithms.
- `CpuBackend = Autodiff<Flex<f32>>` — used by parametric UMAP on the CPU path; `flex` replaced the old `ndarray` backend for parametric UMAP.

Precision policy: UMAP/tSNE dispatch fp32 vs fp64 through `parse_precision`, which honours the user's `use_high_precision` arg or falls back to `auto_precision` (fp64 above `SAMPLE_THRESHOLD_HIGH_PRECISION = 100_000` samples). tSNE is called out as precision-sensitive.

For the sibling Rust crates that own the actual algorithms, see the next section.

## External Rust crates

Three sibling crates (same maintainer) hold most of the real work — `bixverse.gpu` is largely a thin R interface into them. Knowing which crate owns what matters when hunting a bug or extending an algorithm; most GPU kernels do not live in this repo.

- **`ann-search-rs`** — Approximate nearest-neighbour crate; owns CAGRA / IVF / exhaustive kNN plus shared SIMD and GPU-tensor infrastructure that the other sibling crates reuse. Many of the GPU primitives dispatched from here originate there. (feature: `gpu`)
- **`bixverse-rs`** — Rust engine behind the whole `bixverse` ecosystem. This package consumes its GPU-accelerated pieces (linalg, PCA, Harmony, correlations, k-means); the main non-GPU R-facing interface lives in the separate `bixverse` R package. (features: `gpu`, `single-cell`; currently pinned to branch `feat-faster-gpu`)
- **`manifolds-rs`** — Manifold-learning crate: UMAP, tSNE, diffusion maps, PaCMAP, PHATE. Depends on `ann-search-rs` for kNN. GPU coverage is expanding — kNN searches are already GPU, and the UMAP optimiser now has a GPU path too. (features: `parametric`, `gpu`, plus `fft_tsne` off-Windows — the h5 toolchain issue from the README)

## Conventions

- kNN indices returned to R are **1-indexed**; Rust returns 0-based and R adds 1 in `nn_gpu.R::generate_knn_graph`. Matrices returned to Rust are always cells×features / samples×features (row-major from R's perspective).
- Verbosity everywhere: `0L` silent, `1L` normal, `2L` detailed. R-side accepts a boolean or `0/1/2`; funnels through `parse_verbosity()` before crossing into Rust.
- S3 classes: `KMeansClusterGPU` (in `R/classes.R`) implements `manifoldsR::membership` / `get_centroids`. `ParametricUmapModel` has `print` and `predict` methods and can be serialised via `save_parametric_umap` / `load_parametric_umap` (bytes are tagged 0=GPU, 1=CPU by `rs_serialise_parametric_umap`).
- `.onLoad` in `R/zzz.R` calls `S7::methods_register()` — do not remove; single-cell generics need it.
- Package is `lifecycle: experimental`; new user-facing functions get `r lifecycle::badge("experimental")` in the roxygen `@description`.

## Writing style

- No em-dashes (`—` or `--`) in prose you write for this repo (vignettes, README, roxygen, commit messages, PR descriptions). Reads as AI-generated. Use commas, colons, semicolons, or full stops instead.

## Notes and non-obvious things

- `scratch.R` and `scratch_large_data.R` at the repo root are personal experimentation scratchpads — not part of the package, ignored by `.Rbuildignore`. Don't touch unless asked.
- The `document` binary in `src/rust/document.rs` is invoked by `Makevars` after the lib build to regenerate wrappers during install; that's the reason `document.rs` sits alongside `Cargo.toml` and has its own `[[bin]]` entry.
- `configure` / `configure.win` + `tools/config.R` + `tools/msrv.R` implement CRAN-friendly Rust detection and the vendored-crate offline build path (`src/rust/vendor.tar.xz`). Don't hand-edit `src/Makevars` — it is generated from `src/Makevars.in`.
- `bixverse`, `bixverse.plots`, `manifoldsR` are `Remotes:` — assume they are installed from GitHub in dev environments.
